## exam-blueprint

The Claude Certified Architect – Foundations (CCA-F; Pearson VUE code CCAR-F) is Anthropic's first certification, launched 2026-03-12 alongside the Claude Partner Network and its initial $100M partner investment (verified via anthropic.com/news/claude-partner-network). It is a closed-book, online-proctored, scenario-based exam: 60 multiple-choice questions (1 correct of 4), 120 minutes, scaled score 100–1,000 with a 720 pass mark. Questions are organized around production scenarios — each exam draws 4 of a published pool of 6 (Customer Support Resolution Agent, Code Generation with Claude Code, Multi-Agent Research System, Developer Productivity Tools, Claude Code in CI/CD, Structured Data Extraction). Five weighted domains form the blueprint: Agentic Architecture & Orchestration 27%, Claude Code Configuration & Workflows 20%, Prompt Engineering & Structured Output 20%, Tool Design & MCP Integration 18%, Context Management & Reliability 15%. The exam is gated to Claude Partner Network member organizations (membership itself is free); candidate profile is a solution architect with 6+ months hands-on with the Claude API, Claude Code, the Agent SDK, and MCP.

Logistics changed materially on 2026-06-30: delivery migrated from Skilljar + ProctorFree to Pearson VUE (OnVUE online or test centers), the fee rose from $99 (first 5,000 partner-employee seats were free) to a reported $125, retakes formalized to 4 attempts per rolling 12 months with 14/30/90-day waits (retake policy confirmed on Pearson VUE's official Anthropic page), and validity settled at 12 months with a free non-proctored renewal assessment (earlier reports had said 6 months — treat validity as secondary-sourced). Pearson VUE officially lists four Claude credentials: Associate–Foundations (CCAO-F), Architect–Foundations (CCAR-F), Architect–Professional (CCAR-P), and Developer–Foundations (CCDV-F), confirming the multi-tier roadmap Anthropic announced.

Thirteen free Anthropic Academy (anthropic.skilljar.com) courses map to the exam: Claude 101, Claude Code 101, Claude Code in Action, Introduction to Claude Cowork, Building with the Claude API (the 8-hour anchor course), Introduction to MCP, MCP: Advanced Topics, Introduction to Subagents, Introduction to Agent Skills, AI Capabilities & Limitations, AI Fluency: Framework & Foundations, Claude with Amazon Bedrock, and Claude with Google Cloud's Vertex AI. All course names were verified against the live Skilljar catalog; the 13-course-to-domain mapping and lesson counts come from secondary prep sites. Community consensus study load is ~40 hours for someone with production experience. For the app, this means: weight lesson volume by domain (27/20/20/18/15), make every mock exam scenario-clustered rather than isolated trivia, and teach architectural decision-making ("which design is right for this failure mode") rather than API recall — every credible source stresses the exam tests decisions in scenarios, not definitions. The full per-domain topic trees for curriculum design are in the recommendations below.

### Recommendations
- DOMAIN 1 TOPIC TREE — Agentic Architecture & Orchestration (27%, ~14 of 60 lessons): (1) workflows vs agents — predefined code paths vs model-directed loops (Anthropic 'Building effective agents'); (2) the augmented LLM building block (retrieval + tools + memory); (3) the agentic loop: gather context → act via tool → observe result → repeat, and stop conditions; (4) the five composable patterns: prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer — and when each fits; (5) 'start simple': when NOT to build an agent (cost/latency/error tradeoff); (6) subagents: isolated context windows, restricted tool sets, per-agent model choice, specialized system prompts; (7) orchestrator/hub-and-spoke multi-agent design, task decomposition and delegation; (8) parallel vs sequential execution and partial-failure handling across subagents; (9) Claude Agent SDK: query loop, sessions, ResultMessage subtypes, permission modes, hooks, automatic compaction; (10) guardrails: max_turns, budget caps, permission gates, human-in-the-loop approval points; (11) stop_reason inspection and branching in agent loops; (12) multi-agent economics: token multiplication, when single-agent wins; (13) agent evaluation: LLM-as-judge, trajectory/outcome evals, success criteria; (14) session state, checkpointing, resumability.
- DOMAIN 2 TOPIC TREE — Tool Design & MCP Integration (18%, ~10 lessons): (1) tool definition anatomy: name, description, input_schema — description prose quality is THE top selection-accuracy lever; (2) the tool-use loop: stop_reason 'tool_use' → execute → return tool_result blocks → continue; (3) tool_choice modes: auto / any / tool (forced) / none; (4) parallel tool calls and disable_parallel_tool_use; (5) tool error handling: is_error flag, structured actionable error messages, retryable vs terminal failures; (6) strict tool use (strict: true) for guaranteed schema-valid inputs; (7) client tools vs Anthropic server tools (web search, code execution, memory tool); (8) writing tools for agents: response pagination/truncation, token-efficient responses, consolidating workflows into fewer high-level tools; (9) MCP architecture: host / client / server, JSON-RPC 2.0; (10) MCP server primitives: tools (tools/call), resources (resources/read), prompts (templates); (11) MCP advanced primitives: sampling, roots, elicitation, notifications; (12) transports: stdio (local) vs Streamable HTTP (remote) + auth (OAuth/bearer); (13) MCP config scope precedence in Claude Code (local > project > user); (14) choosing between plain tools, MCP servers, and Agent Skills.
- DOMAIN 3 TOPIC TREE — Claude Code Configuration & Workflows (20%, ~11 lessons): (1) CLAUDE.md memory hierarchy: enterprise/managed → user (~/.claude) → project → directory-level, plus import syntax and auto memory; (2) .claude/rules/ with YAML frontmatter and path-scoped rules; (3) settings precedence: managed policy → CLI flags → .claude/settings.local.json → project settings.json → user settings; permission rules MERGE across scopes; (4) permission system and modes: default, acceptEdits, plan, dontAsk/auto, bypassPermissions; (5) Plan Mode: read-only planning before execution; (6) hooks: PreToolUse, PostToolUse, UserPromptSubmit, SessionStart/End, Stop, SubagentStop — exit-code semantics (0 success, 2 blocking error to Claude, other non-blocking); (7) custom slash commands: markdown + frontmatter + arguments; (8) Agent Skills: SKILL.md, frontmatter, progressive disclosure; (9) Claude Code subagents: .claude/agents markdown+YAML, tool scoping, model selection; (10) adding MCP servers (claude mcp add, scopes, transports); (11) headless/CI: claude -p, output formats, --permission-mode, GitHub Actions, automated code review with false-positive minimization; (12) git workflows: commits, PRs, worktrees for parallel sessions; (13) context commands: /clear, /compact, /memory, # shortcut, auto-compact; (14) team standardization: checked-in shared settings/commands/skills, managed policies.
- DOMAIN 4 TOPIC TREE — Prompt Engineering & Structured Output (20%, ~11 lessons): (1) clear/direct instructions, system prompts and role prompting; (2) few-shot/multishot: 3–5 diverse examples wrapped in XML tags — examples beat instructions for format conformity; (3) chain-of-thought and extended thinking; effort/thinking-budget tradeoffs (latency & cost vs quality); (4) XML tags for structure and delimiting; (5) Structured Outputs: output_config.format JSON schema, guaranteed-valid JSON, supported/unsupported schema features, refusal & max_tokens edge cases (VERIFIED against platform.claude.com docs); (6) tool-based extraction vs structured outputs vs (legacy) prefilling — one source (ccaf.joshking.ai) claims prefilling 400-errors on newest models: teach as 'migrate away from prefilling', flag as secondary; (7) validation-retry loops for schema/quality failures; (8) long-context prompting: put large documents at the TOP, quote-extraction-first grounding; (9) prompt templates/variables; positive directives over negations; (10) hallucination mitigation: permission to say 'I don't know', citation grounding; (11) Message Batches API for high-volume extraction (50% discount) — appears in the Structured Data Extraction scenario; (12) defining success criteria and empirical prompt evaluation; (13) AI Fluency 4D framework (Delegation, Description, Discernment, Diligence) — it is exam-mapped via the AI Fluency course.
- DOMAIN 5 TOPIC TREE — Context Management & Reliability (15%, ~9 lessons): (1) context window mechanics; context rot / lost-in-the-middle degradation; (2) context engineering: smallest high-signal token set; three mitigations — pruning, summarization, delegation to subagents; (3) prompt caching: cache_control ephemeral, up to 4 breakpoints, 5-min/1-hr TTL, write/read cost multipliers, minimum cacheable lengths, invalidation rules; (4) context editing API: clear_tool_uses_20250919 and clear_thinking_20251015 with triggers/keep/exclude_tools, cache interaction (VERIFIED against docs); (5) compaction: server-side compact edit, Claude Code auto-compact, Agent SDK compaction; (6) memory tool / memory files to persist state across clears and sessions; (7) count_tokens endpoint for pre-send budgeting; (8) stop_reason taxonomy: end_turn, max_tokens, tool_use, stop_sequence, refusal, pause_turn, model_context_window_exceeded; (9) HTTP error taxonomy: 400/401/403/404/413 non-retryable vs 429/500/529 retryable, exponential backoff, Retry-After compliance; (10) rate limits (RPM/ITPM/OTPM) and tier planning; (11) streaming via SSE for long requests; (12) escalation/HITL design: valid triggers (safety, confidence threshold, policy) vs invalid (vagueness, novelty); (13) structured error propagation and provenance tracking across agent layers; (14) graceful degradation: model fallback, truncation, RAG to keep context lean.
- CURRICULUM STRUCTURE: allocate the ~50+ lessons proportionally to official weights (D1≈14, D3≈11, D4≈11, D2≈10, D5≈9) and order courses D1 → D2 → D3 → D4 → D5 only after a short 'Meet the Exam' intro unit that teaches the blueprint itself (weights, scenario format, scoring) — knowing the blueprint is itself testable meta-knowledge and a strong hook lesson.
- MOCK EXAM DESIGN: mirror the real structure — each of the 3 full mocks should be 60 questions/120 minutes built as 4 scenario clusters drawn from the 6 published scenarios plus standalone items, stratified to the 27/20/20/18/15 weights; per-domain mini-exams should be 15–20 questions. Write distractors as plausible-but-flawed architectures (wrong pattern for the failure mode, cache-hostile ordering, over-agentic design) since every source agrees the exam tests decisions, not definitions.
- FEYNMAN INTEGRATION: end every lesson with an 'explain it simply' prompt targeting the highest-confusion pairs surfaced by this research — workflows vs agents, subagent vs Agent Skill vs MCP server, tool_choice any vs tool, settings merge vs override, prompt caching vs context editing vs compaction — these boundary distinctions are exactly where scenario distractors live.
- CONTENT SOURCING: ground question content in official, stable references — docs at platform.claude.com (tool use, structured outputs, prompt caching, context editing, errors, streaming), anthropic.com/engineering 'Building effective agents' and 'Writing tools for agents', modelcontextprotocol.io spec, and Claude Code docs — rather than blog paraphrases; the 13 Skilljar courses define scope but their exact lesson text is Anthropic's IP, so paraphrase concepts, never mirror course text.
- MAINTENANCE PLAN: build content versioning from day one — this exam changed materially within 4 months of launch (platform, price, retakes, validity, practice exam removed), Anthropic ships new certs (CCDV-F, CCAR-P, CCAO-F are already listed at Pearson VUE) and new API features quarterly; tag every question with its source doc URL so a quarterly re-verification sweep is cheap. ## duolingo-mechanics

Duolingo's 2025/2026 gamification stack is a tightly-coupled loop of five systems: (1) a linear PATH (sections → units → levels → lessons, with Legendary levels, unit reviews, and jump-ahead tests) that removes all choice about "what to study next"; (2) an XP ECONOMY (10 XP base lessons, +5 combo bonus, 2x boosts in 15-minute windows, timed challenges worth 40-60 XP) that feeds (3) LEAGUES (10 tiers Bronze→Diamond, cohorts of 30, weekly Monday reset, top ~7-20 promoted / bottom ~5 demoted, plus a 3-phase Diamond Tournament); (4) STREAKS as the retention backbone (equippable streak freezes at 200 gems, repair, milestone celebrations, Streak Society perks at 7/30/100/365 days, friend streaks, and a home-screen widget whose escalating "sad Duo" art raised commitment ~60%); and (5) a GEMS economy earned via daily-quest chests (bronze ~5 / silver ~10 / gold ~15 gems + XP boosts) and spent on streak freezes, heart/energy refills (~350-650 gems), Legendary attempts (100 gems), and timed-challenge entries. Mistake-limiting (5 hearts, ~4-6h regen, practice-to-earn) was being replaced during 2025 by a 25-unit "Energy" system that REWARDS correct streaks with energy back — a notable pivot away from pure punishment that we should copy.

The habit machinery around the loop is equally specific: 3 daily quests/day escalating in difficulty, weekly Friend Quests (100 gems + 30-min 2x boost for both partners), monthly challenge badges (complete ~25-50 quests), 10-tier achievement tracks (Wildfire, XP Olympian, Word Collector, Champion, Legend), a Practice Hub with automatic mistakes-review decks, an onboarding that delays signup until AFTER motivation survey → daily-goal pick → placement-or-scratch choice → first completed lesson, an "investment wager" commitment device (+14% D7 retention), and an AI-bandit notification system with meme-famous passive-aggressive copy that self-mutes after ~7 ignored reminders ("These reminders don't seem to be working"). Juice is delivered via Rive-driven character state machines (lip-sync, emotional reactions), chirp/boing sound design, haptics on correct answers, in-lesson combo counters that flare at 5-in-a-row, segmented progress bars that surge per answer, and chest-opening reward ceremonies.

For an ADHD-first CCA-F exam app, clone the structure but soften the documented dark patterns: Duolingo's own critics (and its Energy pivot) identify hearts-as-punishment, streak-loss anxiety on multi-hundred-day streaks, guilt/shame notification copy, and paywall pressure at moments of failure as the manipulative edges. Keep the loop (path, XP, quests, streaks, leagues, juice), but make mistakes cost nothing or even generate review-deck value, make streak repair generous and shame-free, and keep notification copy playful-supportive rather than guilt-based — which also aligns with the app's Feynman-technique pedagogy where errors are the raw material for "identify gaps."

- STREAK SOCIETY: tiered club — 7-day streak: 3 free days of Super; 30 days: exclusive app icon / welcome chest; 100 days: 3 bonus streak freezes; 365 days: VIP status with visible-streak perks on leaderboards (duoplanet.com/duolingo-streak-society, lingoly.io/duolingo-streak-society)
- FRIEND STREAKS (2024/25 feature): separate shared streak with up to 5 friends; both must complete a daily lesson to keep each pair-streak alive (blog.duolingo.com/friend-streak)
- HEARTS (legacy system, still live for many users): 5 hearts, lose 1 per mistake; regen 1 heart per ~4-6 hours (5h commonly cited); refill options: ~350-450 gems in-lesson / ~360 outside, 650 gems for full 5 (sources vary — treat exact gem prices as tunable); earn 1 heart per completed practice session or ad watch; Super = unlimited hearts (duolingo.fandom.com/wiki/Hearts, duolingoguides.com/duolingo-hearts-refill, support.duolingo.com hearts article)
- ENERGY (2025 replacement, A/B rolling out since July 2025): 25 energy units; correct answer costs 1, wrong answer 1-2; every 5-in-a-row triggers a lightning animation refunding 1-5 energy — Duolingo's stated rationale: beginners were 2x more likely to run out of hearts mid-lesson, so the new system rewards success instead of only punishing failure; received significant user backlash for limiting free play (blog.duolingo.com/duolingo-energy, duolingo.fandom.com/wiki/Energy, duoplanet.com/duolingo-energy-system, classcentral.com/report/duolingo-breaks-hearts-for-energy)
- GEMS EARN RATES: daily-quest chests (bronze ~5 gems, silver ~10, gold ~15 or an XP boost), bonus chest for completing all 3 daily quests, Friend Quest = 100 gems, league top finishes, streak milestones, achievement completions, optional rewarded ads (10-30 gems), daily-goal chests (duoplanet.com/duolingo-gems-and-lingots, duoplanet.com/duolingo-chests, lingoly.io/earn-gems-duolingo)
- GEMS SPEND SINKS: streak freeze 200, heart/energy refills ~350-650, Legendary attempts 100, timed-challenge entry 100, streak repair ~200, wager-style items; sinks deliberately exceed free earn rate to create Super upsell pressure (duoplanet.com/duolingo-gems-and-lingots, growth.design/case-studies/duolingo-user-retention)
- LEAGUES: 10 tiers — Bronze, Silver, Gold, Sapphire, Ruby, Emerald, Amethyst, Pearl, Obsidian, Diamond; cohorts of 30 users matched at similar tier; week resets Monday 4:00 AM GMT; promotion zone varies by tier (~15-20 promoted in low leagues shrinking to ~10 higher up), bottom ~5 demoted (Diamond: ranks 26-30 demoted); unlocked only after ~10 lessons; leagues drive ~+25% lesson completion per Deconstructor of Fun (duolingo.fandom.com/wiki/League, duolingo.deconstructoroffun.com/mechanics/leagues, duoplanet.com/duolingo-leagues guide, duolingo.com/help/leaderboards-and-league)
- DIAMOND TOURNAMENT: finish top 10 in Diamond to enter a 3-phase bracket (Quarterfinals → Semifinals → Finals, ~top 10/10/7 advance weekly); top 3 in finals win gems, a 30-min XP boost, and an exclusive winner banner; all finalists get a profile banner (lingoly.io/duolingo-diamond-tournament, duocorner.com/duolingo-diamond-tournament, blog.duolingo.com/duolingo-leagues-leaderboards)
- DAILY QUESTS: 3 per day since 2022, escalating difficulty (easy→bronze chest, medium→silver, hard→gold with XP-boost odds) + a bonus chest for completing all three; example quests: 'Earn 50 XP', 'Complete 3 lessons', 'Score 90%+ in 3 lessons', 'Get a 10-in-a-row combo', 'Spend 15 minutes learning' (duoplanet.com/duolingo-challenges, happilyevertravels.com/duolingo-daily-quests, duolingo.fandom.com/wiki/Quests)
- FRIEND QUESTS: weekly random pairing with a friend, cooperative goal (combined XP, perfect lessons, etc.), ~5 days to finish; both partners get 100 gems + 30 minutes of 2x XP; Friend Quests award more monthly 'quest points' than daily quests (blog.duolingo.com/friends-quests, duolingoguides.com/what-is-a-quest-in-duolingo)
- MONTHLY CHALLENGES: complete ~25-50 quests within the calendar month (target scales with activity level) to earn that month's exclusive collectible badge shown on profile; 2025 redesign made badges character-driven and moved them to the Profile tab (duoplanet.com/duolingo-challenges, lingoly.io/duolingo-monthly-badge)
- ACHIEVEMENTS: ~10-tier progressive tracks — Wildfire (streak: 3→365 days, 10 levels), XP Olympian née Sage (100→30,000 XP), Word Collector née Scholar (50→2,000 words), Champion (advance through the 10 leagues), Legend (up to 250 legendary levels), plus one-offs like Early Riser; each tier pops a badge ceremony and often gems (duoplanet.com/duolingo-achievements-guide, lingoly.io/duolingo-achievements, duolingo.fandom.com/wiki/Achievements)
- PRACTICE HUB: dedicated tab with Mistakes Review (every in-lesson error is logged automatically and resurfaced; sessions up to 10 questions), targeted Speaking practice, Listening practice, Words review, and unit review; unlimited mistakes-review is a Super perk while basic practice sessions are free; practicing also earns back a heart (blog.duolingo.com/guide-to-duolingo-practice-hub, duoplanet.com/duolingo-practice-hub)
- EXERCISE TYPES: translate sentence (tap word-bank tiles or free-type), select-the-image for new vocab, tap-the-matching-pairs (text-text and audio-text), fill-in-the-blank, 'type what you hear' dictation (with slow-replay button), 'what do you hear' multiple choice, speak-this-sentence (speech recognition), complete-the-conversation, plus Stories (interactive dialogue with comprehension checks) and DuoRadio (podcast-style passive listening with periodic checks) (duolingo.fandom.com/wiki/Exercise, duolingo.fandom.com/wiki/Duolingo_Stories, blog.duolingo.com/duoradio-listening-practice)
- DUOLINGO SCORE (Oct 2024): a 0-160 proficiency number shown next to the course flag, mapped to CEFR bands (0-10 early A1 ... 115-130 high B2); designed to replace streak/XP as the 'am I actually learning' metric — a direct analog for a 'predicted exam score 100-1000' meter in our CCA-F app (blog.duolingo.com/duolingo-score, duoplanet.com/duolingo-score)
- ONBOARDING ORDER (deliberate): language pick → 'how did you hear' → motivation survey (travel/work/school) → daily goal selection (Casual ~5 min → Intense ~20 min) → binary choice 'Start from scratch' or 'Find my level' (placement test) → FIRST FULL LESSON → only then account signup; delayed signup + only-two-options choices minimize decision fatigue (theappfuel.com/casestudies/three-learnings-from-duolingos-onboarding, growth.design/case-studies/duolingo-user-retention, junoschool.org duolingo onboarding article)
- DAY-1/EARLY RETENTION TRICKS: 'investment wager' commitment step (+14% D7 retention per growth.design); streak starts counting from day 1's first lesson; welcome-back rewards of ~100 gems for lapsed users; simplified 'happy path' easier lessons for new/returning users; quick-start big green button eliminating choice (Hick's law); deliberate 'you hit your goal, you can stop now' exit points to avoid endless-task fatigue (growth.design/case-studies/duolingo-user-retention)
- NOTIFICATIONS: AI bandit algorithm picks per-user copy/timing (blog.duolingo.com/hi-its-duo-the-ai-behind-the-meme); tone is playful passive-aggressive guilt ('Don't let Duo down!', crying Duo); the single most famous high-performing message is the self-aware bail: 'Hi, it's Duo. These reminders don't seem to be working. We're going to stop sending them for now.' — sent after ~7 ignored reminders, and the auto-muting itself paradoxically drives returns; reminders are timed to the user's habitual practice hour plus an evening streak-danger alert (tinomwadeyi.substack.com, solve-marketing.agency Duolingo case, growth.design)
- JUICE/ANIMATION: characters are Rive state machines (per-phoneme lip-sync via visemes, emotional reaction states blended programmatically) — this is why the app 'feels alive'; correct answers = green flash + rising chirp + light haptic; wrong = muted thud/boing, no harsh buzzer; in-lesson combo counter ignites at 5-in-a-row with flame/lightning animation (Energy system refunds energy at each 5-streak); segmented progress bar surges forward with a springy fill per correct answer; lesson-end sequence: XP tally count-up → combo/accuracy bonus reveal → chest/reward ceremony → streak flame ignition; streak milestones get full-screen takeover animations (blog.duolingo.com/world-character-visemes, elisawicki.blog Rive analysis, blog.duolingo.com/streak-milestone-design-animation, medium.com Bundu micro-interactions)
- BUSINESS OUTCOME EVIDENCE: gamification stack credited with cutting churn from ~47% to ~28% in major markets and +36% YoY DAU growth (2025); leagues +25% lesson completion; streak mechanic ~2x daily retention (deconstructoroffun.com Duolingo DAU article, duolingo.deconstructoroffun.com/mechanics/streaks, strivecloud.io Duolingo gamification)
- DARK-PATTERN INVENTORY (documented criticisms to soften): (1) hearts punish mistakes and stall beginners — Duolingo itself conceded this with the Energy pivot; (2) long-streak loss aversion produces genuine anxiety/identity attachment (users feel losses ~2x gains; 500-day streak loss reported as distressing), monetized via freeze/repair purchases; (3) guilt/shame notification and mascot copy; (4) gem sinks priced above free earn rates to force Super upsell at the exact moment of failure (out of hearts mid-lesson); (5) splash-screen offer stacking that overwhelms returning users; (6) engagement metrics (streak/XP) optimized over actual learning depth (drracheltaylor.substack.com streak addiction, screenwiseapp.com loss-aversion guide, medium.com/@varsharam guilt essay, growth.design, classcentral.com energy report)

### Recommendations
- Clone the path skeleton 1:1 for CCA-F: 5 Sections = the 5 exam domains, ~10 units per domain (~50 lessons total), each unit ending in a unit-review node and a Legendary-style 'no-hints, stricter accuracy' challenge that gates the gold state — this maps cleanly to per-domain mini-exams and the 3 full mocks as section-end 'boss' nodes.
- Adopt the Energy model, not Hearts: since Duolingo itself is abandoning punishment-only hearts (beginners 2x more likely to stall), start with a generous energy pool where correct 5-in-a-row streaks refund energy, and never hard-block studying — for an ADHD-first paid-nothing study app there is no upsell reason to gate practice; keep the mechanic purely as juice/pacing.
- Copy the XP economy numbers as defaults and tune later: 10 XP base + 5 combo per lesson, 20 XP unit-completing lesson, 40 XP legendary challenge, 5 XP gold-unit re-review (this anti-farming decay is important so users push into weak domains instead of re-grinding easy ones), 15-minute 2x boosts from an Early Bird chest and quest gold chests, 40-60 XP timed challenges (Match-Madness-style term-pair matching works perfectly for MCP/tool-design vocabulary).
- Implement the full quest ladder: 3 escalating daily quests (bronze/silver/gold chests: ~5/10/15 gems, gold sometimes a 2x boost) + all-three bonus chest, weekly cooperative Friend Quests (100 gems + 30-min boost for both — pairs well with real Supabase friends), and a monthly collectible badge for ~30 completed quests; quests should be auto-satisfiable by normal study so they feel like recognition, not chores.
- Make streaks generous by design: 200-gem streak freezes with 2 equipped free from day one, cheap repair, milestone ceremonies at 7/30/100 days (exam-relevant horizon), a Streak-Society-style perk track, and an iOS home-screen widget (Expo supports this via widget extensions) with escalating-but-cute mascot art — the widget is Duolingo's single highest-leverage retention surface (~60% commitment lift).
- Copy the onboarding order exactly: exam-date + motivation question → daily goal pick (5/10/15/20 min) → 'Start from scratch' vs 'Find my level' placement quiz → complete the first real lesson BEFORE any Supabase signup → then the +14% 'wager' commitment step; and clone the Duolingo Score as a live 'Predicted CCA-F score: 100-1000' dial that updates with performance — for an exam app this is even more motivating than XP because 720-to-pass gives it a concrete finish line.
- Soften the documented dark patterns per the ADHD-first mandate: no shame copy anywhere (mistakes route into the Feynman 'identify gaps' review deck and are framed as progress), notifications playful-supportive with the self-aware auto-mute after ~5-7 ignored sends, no monetization pressure at failure moments, and a 'streak paused, not broken' state instead of catastrophic streak loss; use leagues opt-out-able since social comparison can be aversive for some neurodivergent users.
- Budget real effort for juice: use Rive (or Lottie + Reanimated) for a mascot with reaction states, expo-haptics light tick on correct / soft thud on wrong, rising-pitch chirp audio, a springy segmented progress bar, 5-in-a-row combo flare, and a lesson-end XP-tally → bonus → chest → streak-flame ceremony — Duolingo's data shows the ceremony sequence, not the content, is what makes the loop addictive.

### Risks
- Exact numeric values (heart refill gem costs 350 vs 360/450/650, base lesson XP 10 vs 20, streak-repair pricing, promotion-zone sizes) vary across sources and Duolingo A/B tests — treat every number here as a sane default to tune, not gospel; the app A/B tests constantly and web/iOS values differ.
- Duolingo was mid-migration from Hearts to Energy during 2025 with significant user backlash (no opt-out, perceived free-tier throttling) — cloning either system too literally imports a mechanic Duolingo itself hasn't stabilized; the safe move is the reward-loop half (5-in-a-row refunds) without the depletion-blocking half.
- Streak loss-aversion is the most powerful AND most criticized mechanic (documented anxiety, addiction-pattern criticism, parental guides warning about it) — an ADHD-first app that copies it at full strength contradicts the no-shame design goal and could actively harm the target audience; the softening recommendations trade some retention power for user wellbeing, a deliberate product decision Nate should sign off on.
- Several sources are enthusiast fan sites (duoplanet, lingoly, duolingoguides, fandom wiki) rather than official Duolingo documentation; official blog posts confirm the existence and rationale of mechanics but rarely publish exact economy numbers, so fan-site figures carry single-source risk.
- Leagues with real leaderboards need enough concurrent users to fill 30-person cohorts — a niche CCA-F exam app will likely have tiny cohorts at launch, so plan for ghost/bot fill, smaller cohorts (e.g. 10), or async 'beat your past week' fallback, otherwise the league tab reads as dead and demotivates.
- Duolingo's retention stats quoted in secondary sources (+14% D7 wager, 60% widget lift, 47%→28% churn) are point-in-time claims from case studies and may not transfer to an exam-prep context with a natural end date (users churn deliberately after passing the exam — success looks like churn).

## expo-stack

Recommended 2026 stack: Expo SDK 57 (expo@~57.0.4, latest on npm as of 2026-07-13) with React Native 0.86.0 and React 19.2.3, expo-router ~57.0.4 (Expo now version-aligns all its packages to the SDK number), TypeScript. Animation core: react-native-reanimated 4.5.x + react-native-worklets 0.10.x (Reanimated 4 split worklets into a separate required package) and react-native-gesture-handler ~2.32.0 — note gesture-handler v3.0.2 is npm "latest" but SDK 57 pins ~2.32.0, so always install via `npx expo install`, never raw npm latest. For Duolingo-style juice: use Reanimated 4 for all interaction feedback (button squish, XP counters, streak flames), lottie-react-native 7.3.8 for celebration/mascot animations (recommended over Rive: huge free LottieFiles ecosystem, bundled in Expo SDK/Go, no design-tool pipeline; Rive's real package is rive-react-native@9.8.3 — the name "@rive-app/react-native-rn" given in the task DOES NOT EXIST on npm, 404, classic slopsquat trap), react-native-fast-confetti 2.0.1 (Skia-based, actively maintained) for confetti since react-native-confetti-cannon is unmaintained since 2022, and @shopify/react-native-skia 2.6.2 (SDK pin) available for custom particles. expo-haptics 57.0.0 for haptics; expo-audio 57.0.0 for sound effects (expo-av is legacy — still published at 16.0.8 but has no sdk-55/56/57 dist-tags, i.e., off the SDK release train; expo-audio is the stable replacement and is in Expo Go).

Styling: NativeWind 4.2.6 recommended for this app. Rationale: a heavily custom, themed, game-like UI needs fast iteration on hundreds of one-off component styles, and NativeWind gives design-token theming (colors/spacing via Tailwind config + CSS vars for dark mode), the largest ecosystem/community, and is by far the most AI-codegen-friendly (relevant since this app will be built with Claude Code); drop to plain StyleSheet/Reanimated styles inside perf-critical animated components. react-native-unistyles 3.3.0 is the performance-maximalist alternative (C++ core, zero re-renders) but has a smaller community, steeper API, and pulls in react-native-nitro-modules — fine, but not worth the friction here. State: zustand 5.0.14 with persist middleware backed by react-native-mmkv 4.3.2 (+ its required peer react-native-nitro-modules 0.36.1): synchronous, encrypted-capable, order-of-magnitude faster than AsyncStorage, built for New Architecture (RN 0.86 is new-arch-only, so this is the correct choice; AsyncStorage 2.2.0 is the SDK-pinned fallback only if you insist on Expo Go). Local offline-first DB: expo-sqlite 57.0.0 + drizzle-orm 0.45.2 (pin 0.45.x — a 1.0.0 beta is in flight) with drizzle-kit migrations and Drizzle's expo-sqlite live-query support; ship the 600+ questions as a bundled SQLite db, write progress/SRS rows locally, sync to Supabase (@supabase/supabase-js 2.110.3) for accounts/leaderboards. WatermelonDB 0.28.0 is not recommended: last publish July 2025 (a year stale), its sync engine is overkill next to Supabase, and it adds native-module friction. Charts/progress rings: react-native-svg 15.15.4 (SDK pin) + Reanimated animated props for XP/progress rings (a ring is ~20 lines with animated strokeDashoffset); add victory-native 41.26.0 (Skia-based, same rendering stack) only if you need real charts for stats screens.

Install path to the physical iPhone (user has Mac + Xcode): Expo Go is NOT viable for this app — react-native-mmkv/nitro-modules, unistyles, and rive are not bundled in Expo Go, remote push was removed from Expo Go in SDK 53, and Expo Go only supports the single latest SDK. So build a development build from day one with expo-dev-client 57.0.5. The lowest-friction, zero-cost path: connect the iPhone via USB, enable Developer Mode (iOS 16+), sign into Xcode with a FREE Apple ID (Personal Team), and run `npx expo run:ios --device`. This compiles locally, signs with free provisioning, and installs directly — haptics, local notifications, Lottie/Reanimated/Skia, MMKV, SQLite all work. Free-account constraints: the provisioning profile expires every 7 days (re-run the one command weekly with the phone plugged in), max ~3 sideloaded apps per device / 10 App IDs per week, and no push-notification entitlement — but streak reminders don't need push: expo-notifications 57.0.3 LOCAL scheduled notifications require no entitlement, no server, and work fine with a free Apple ID. EAS Build's free tier (15 iOS + 15 Android builds/month, low-priority queue) does NOT help for device installs without payment: EAS ad-hoc/internal distribution requires a paid $99/yr Apple Developer Program membership to create ad-hoc provisioning. Recommended upgrade trigger: buy the $99 membership when weekly re-signing gets annoying or when you want TestFlight (90-day builds, install over the air) and real remote push. After the first `expo run:ios --device`, day-to-day development is pure JS hot reload over Wi-Fi via `npx expo start` — you only rebuild natively when adding a new native module or when the 7-day cert lapses.

## supabase-architecture

**Supabase backend architecture for the CCA-F study app (Expo/React Native, single-developer, personal iPhone install).** Client layer: `@supabase/supabase-js` with `@react-native-async-storage/async-storage` as the auth storage adapter, plus `react-native-url-polyfill` (still listed in Supabase's RN quickstart deps). Harden session storage with Supabase's documented `LargeSecureStore` pattern (`expo-secure-store` + `aes-js` + `react-native-get-random-values`: AES-256 key in SecureStore, encrypted session in AsyncStorage). `createClient` options per docs: `{ storage, autoRefreshToken: true, persistSession: true, detectSessionInUrl: false }`, plus the documented AppState listener calling `supabase.auth.startAutoRefresh()` when active and `stopAutoRefresh()` otherwise. Auth: Sign in with Apple is **not possible** on a free Apple Developer account — the `com.apple.developer.applesignin` entitlement requires paid Apple Developer Program membership; free Personal Team provisioning can't use it. So the design is: **anonymous sign-in on first launch** (instant, zero-friction — ideal for ADHD onboarding) → later upgrade to a permanent account via **email OTP** (`signInWithOtp` + `verifyOtp({ email, token, type: 'email' })`, with `{{ .Token }}` in the email template so a 6-digit code is sent instead of a deep-link magic link, which is awkward on native). Anonymous users get linked via `updateUser({ email })`; RLS can distinguish them via the `is_anonymous` JWT claim.

**Content: bundle it, don't put it in Postgres.** With 600+ questions and ~50 lessons, ship all course/unit/lesson/question content as versioned JSON (or typed TS modules) inside the app bundle, validated at build time. This gives true offline-first (full lessons and mock exams on a subway with no network), zero latency, zero egress, and no RLS complexity for public content; iteration speed is preserved because EAS Update can push content fixes over-the-air without a store build. The one discipline required: stable string IDs (slugs) for lessons/questions, because all server-side user rows (progress, SRS state, exam answers) key on them; record a `content_version` on progress rows. Postgres then stores **only user data**: `profiles` (id = auth.users.id, display_name, avatar, timezone, total_xp, gems — **never email**; email stays in auth.users), `user_progress` (PK user_id+lesson_id, status, best_score, crowns), `xp_events` (append-only: id, user_id, amount, source, source_id, `client_event_id uuid UNIQUE`, occurred_at, created_at), `streaks` (current/longest, last_activity_date, freezes), `hearts_state` (hearts, max, last_refill_at), `league_cohorts` (id, week_start, tier), `league_members` (cohort_id+user_id PK, weekly_xp denormalized), `user_quests`, `user_achievements` (definitions bundled in-app), `exam_attempts` (exam_id, answers jsonb, raw/scaled score, passed, duration), `srs_reviews` (PK user_id+question_id: due_at, interval, ease, reps, lapses — SM-2/FSRS state), `feynman_submissions` (concept_id, transcript, grade jsonb, model, graded_at).

**RLS and the leaderboard read path.** Enable RLS on every user table with owner policies of the form `using ((select auth.uid()) = user_id)` — wrapping `auth.uid()` in a sub-select is Supabase's documented perf optimization (initPlan caching; up to ~95% faster in their benchmark). `xp_events` is insert+select only for the owner (no update/delete) to protect log integrity. Critical verified caveat: Postgres views are owned by `postgres` and **bypass RLS by default**; on Postgres 15+ create any view `WITH (security_invoker = on)`. For the leaderboard, which needs cross-user reads, the cleanest safe path is an **RPC**: a `security definer` function `get_leaderboard()` (search_path pinned, defined outside exposed schemas or carefully audited) returning only `(rank, display_name, weekly_xp, is_me)` for the caller's cohort — column-limited by construction, avoids recursive-RLS headaches of a "same-cohort SELECT" policy, and can never leak emails because emails aren't in public tables at all. Weekly league rollover runs **server-side**: a SQL function `run_league_rollover()` (close week, rank from xp_events, promote/demote, create new cohorts of ≤30, assign active users) scheduled by `pg_cron` at `0 0 * * 1`; use the documented pg_cron + pg_net → Edge Function pattern (Vault-stored URL/token) only if the rollover must also send push notifications. Client-side assignment is rejected: race conditions, requires the app to be open, trusts the client.

**Edge Functions, offline sync, and dev workflow.** Edge Function `grade-feynman` (JWT verification on): receives `{concept_id, transcript}`, calls the Anthropic Messages API with `ANTHROPIC_API_KEY` read via `Deno.env.get()` — set with `supabase secrets set` in prod and `supabase/functions/.env` locally, so the key never ships in the app bundle — returns a structured grade `{score, gaps[], simplified_feedback}` (use tool-use/JSON output) and inserts into `feynman_submissions`; add a per-user daily grading cap enforced server-side. Offline sync: **event log wins over last-write-wins for XP** — queue `xp_events` locally (expo-sqlite/AsyncStorage queue) with client-generated UUIDs, flush on reconnect via `ON CONFLICT (client_event_id) DO NOTHING` for idempotent replay; totals/streaks derive server-side (trigger-maintained `profiles.total_xp`, streaks computed from event dates in the user's timezone). LWW with an `updated_at` guard is fine for naturally idempotent per-row state (`srs_reviews`, `user_progress`, `hearts_state`). Dev workflow: `supabase init` + `supabase start` (Docker) locally; migrations via `supabase migration new`/`db diff`, `supabase db reset` + `seed.sql`; then `supabase link --project-ref`, `supabase db push`, `supabase functions deploy`. Manual steps for Nate: create the hosted project, enable anonymous sign-ins, edit the Magic Link email template to `{{ .Token }}`, enable pg_cron/pg_net extensions, add Vault secrets, run `supabase secrets set ANTHROPIC_API_KEY=...`, and accept free-provisioning's 7-day reinstall cycle on the iPhone.

## feynman-pedagogy

**Feynman loop operationalized.** Every lesson (3–5 min, ADHD-friendly) runs the four Feynman stages as a fixed spine: (1) LEARN — a concept card that leads with a plain-language analogy FIRST ("An MCP server is a universal power adapter: any tool can plug into any AI"), then 2–3 plain sentences, then a labeled "exam words" strip with the canonical terminology and a tiny code/config snippet where relevant; max 2 concepts per lesson. (2) PRACTICE — 6–10 exercises from the 9-type system below, ramping difficulty within the lesson. (3) EXPLAIN IT BACK — the user types or dictates a 2–3 sentence explanation "as if to a smart 12-year-old"; a Supabase Edge Function sends it to Claude (claude-haiku-4-5, structured outputs) with the concept's canonical key points, and gets back JSON: covered_points, missing_points, jargon_flags, misconception, simple_score 1–5, and one encouraging next_step_hint. (4) IDENTIFY GAPS + REFINE — the UI renders covered points as a filling "coverage meter" (never red X's), surfaces the single highest-value gap as a micro-card, and offers one optional one-tap "refine my explanation" retry. Explain-back never costs hearts, is always skippable, and never blocks progress (on network failure: accept, queue for later grading, award neutral XP). Explanations are also re-triggered from the spaced-repetition deck ("re-explain from memory" at 1d/3d/7d), turning the Feynman step into retrieval practice.

**Exercise system → CCA-F formats.** Nine types, each tagged {concept_id, domain, difficulty 1–3} so the SRS/mastery engine can select: multiple choice (maps 1:1 to exam single-response; distractors seeded from real misconceptions harvested from the grading endpoint's `misconception` field), select-all (exam multiple-response; introduce only post-mastery), match-pairs (terminology load: MCP primitives, hook names, effort levels — warmup/low-energy exercise), fill-in-the-blank on CLAUDE.md/MCP-config/settings.json/tool-schema snippets (word-bank → free-type; trains the Claude Code Configuration and Tool Design domains at the exact surface the exam tests), order-the-steps (agent loop, tool_use→execute→tool_result round trip, context-management flows; later tiers add a decoy step), spot-the-bug (tap the broken line in a tool schema/config; trains the evaluative skill scenario questions demand), scenario cards (3–4 sentence mini-case → best architecture choice; the direct mirror of the exam's scenario items and the backbone of mini/mock exams), true/false speed rounds (45–60s dopamine bursts for warmups, streak repair, quests), and the explain-back capstone. Hearts apply only to MC/select-all/scenario; match, speed rounds, and explain-back are consequence-free.

**Grading call economics (verified via the claude-api skill, cached 2026-06-24).** Haiku 4.5 (`claude-haiku-4-5`) at $1/1M input, $5/1M output is comfortably sufficient — the task is constrained rubric-matching against provided key points, not open reasoning. A call is ~1,500–1,700 input tokens (compact ~1,200-token system rubric + 2 few-shot examples, plus a ~300–400-token payload of concept key points and the learner's explanation) and ~150–250 output tokens of JSON → **≈$0.002–0.003 per grading call**; with a 1.3× retry factor, ~$0.0035 per completed Feynman step, so a user finishing all ~50 lessons costs roughly **$0.20 in grading spend**. Do NOT rely on prompt caching: Haiku 4.5's minimum cacheable prefix is 4,096 tokens, so a lean rubric prompt silently won't cache — at these prices that's fine. Use `output_config.format` (json_schema, additionalProperties:false) for guaranteed-parseable JSON; do not send `effort` (errors on Haiku 4.5). Rate-limit gradings per user (e.g., 60/day free) and log `usage` per call to a Supabase table for cost monitoring.

### Recommendations
- [Lesson loop] Fix the lesson spine as: concept card (analogy first → plain explanation → 'exam words' strip) → 6–10 exercises → explain-it-back → gap micro-card + optional one-tap refine → wrap with XP/identity framing ('You can now explain subagents'). Cap at 2 concepts and ~5 minutes per lesson; the obvious-next-action button is always the single largest tap target (ADHD design).
- [Lesson loop] Make explain-back shame-proof by construction: never costs hearts, always skippable (with a small XP bonus for completing), renders results as a coverage meter that fills (covered points light up green; missing points stay neutral gray, never red), and shows exactly ONE next_step_hint — not a list of everything wrong.
- [Lesson loop] Support dictation via iOS speech-to-text into the text field (expo-speech-recognition / native dictation) and grade the transcript identically — lowers friction for the 'explain out loud' Feynman mode.
- [Lesson loop] Degrade gracefully: if the edge function times out or errors, accept the explanation, enqueue it for async grading (Supabase table + retry), award neutral XP, and move on — a network call must never block the dopamine loop.
- [Rubric prompt] Use this system prompt (fixed, versioned in the content repo): 'You are the Explain-It-Back coach in a study app for the Anthropic Claude Certified Architect exam. A learner explained a concept in their own words, as if to a smart 12-year-old. Grade ONLY against the key points provided. Anchors for simple_score: 1=restates jargon or incoherent; 2=memorized phrasing, little own understanding; 3=correct but textbook-ish, some unexplained jargon; 4=clear, own words, at most one unexplained term; 5=vivid and simple, uses an analogy or everyday example, zero unexplained jargon. Rules: covered_points/missing_points use ONLY the provided key-point ids — a point counts as covered if its meaning is expressed even in casual words; jargon_flags lists technical terms used WITHOUT explanation (ignore the allowed_terms list); misconception is one short sentence if the learner states something factually wrong, else null; next_step_hint is ONE sentence, ≤25 words, second person, encouraging, targeting the single most valuable missing point or the misconception — never use "wrong", "incorrect", "failed", or letter grades. Return only JSON matching the schema.' Append 2 few-shot examples (one strong, one gappy explanation).
- [Rubric prompt] User message is a compact JSON payload: {concept_name, key_points: [{id, text}] (3–5 canonical points from the content DB), allowed_terms: [...], learner_explanation}. Returning key-point IDs (not prose) is what makes the coverage meter deterministic and diff-able across retries.
- [Edge function] Supabase Edge Function (Deno/TS) → Anthropic API: model `claude-haiku-4-5`, max_tokens ~500, `output_config: {format: {type: 'json_schema', schema: ..., additionalProperties eliminated}}`, no effort/thinking params; validate the parsed JSON server-side, log {user_id, concept_id, usage.input_tokens, usage.output_tokens, simple_score} to a grading_events table; enforce a per-user daily grading quota (e.g., 60/day free tier) as both cost and abuse control.
- [Cost] Skip prompt caching for the grading prompt (below Haiku 4.5's 4,096-token cacheable minimum; total spend is fractions of a cent anyway). If a premium 'deep weekly feedback' feature is added later (Sonnet 5 at $3/$15 analyzing a week of explanations), price/gate it separately — never put Sonnet in the per-exercise hot path.
- [Exercises] Multiple choice: use everywhere; progression recall → application → scenario-wrapped; build distractors from the misconception field harvested from real user explain-backs (a self-improving distractor bank unique to this app).
- [Exercises] Select-all-that-apply: introduce a concept only after single-MC mastery; progression 2-of-4 → 3-of-6; maps to the exam's multiple-response items — always state 'select all that apply' exactly as the exam does.
- [Exercises] Match-pairs: 3 → 5 pairs, then definition↔example matching; ideal warmup and low-energy filler; carries the terminology load (MCP tools/resources/prompts, hook events, permission modes, effort levels, context-management terms).
- [Exercises] Fill-in-the-blank on real artifacts: cloze CLAUDE.md directives, .mcp.json / MCP server config, settings.json permissions, tool input_schema JSON; progression word-bank single blank → multi-blank → free-type; this is the highest-fidelity trainer for the Claude Code Configuration and Tool Design & MCP domains.
- [Exercises] Order-the-steps: sequence the agent loop (gather context → act → verify → repeat), the tool-use round trip, and context-compaction flows; tier 3 adds a decoy step that must be left out — trains the process reasoning behind Agentic Architecture scenario items.
- [Exercises] Spot-the-bug: broken tool schema (missing required, wrong type name, bad enum), misconfigured MCP entry, CLAUDE.md antipattern; progression obvious bug → subtle bug → 'which fix is correct'; this is the evaluative-judgment trainer that scenario questions reward.

### Risks
- Official CCA-F domain weightings and question-format mix are unverified — the 24/22/18/18/18 blueprint is a placeholder; if the real blueprint differs materially, mock-exam domain reports and readiness verdicts will miscalibrate. Keep weights in config, not code.
- The linear scaled-score approximation cannot reproduce Anthropic's real equating (likely IRT-based); users near the 720 line may get a false pass/fail signal — the ≥770 'likely ready' buffer and explicit 'estimate' labeling mitigate but don't eliminate this.
- LLM grading variance: Haiku 4.5 may occasionally mis-map a casually-worded explanation to key-point IDs (false 'missing point'), which is exactly the shame moment the design tries to avoid — mitigate with few-shot examples, 'counts as covered if the meaning is expressed' rule, generous tie-breaking toward covered, and an in-UI 'I did cover this' feedback tap that logs disagreements for prompt tuning.
- Pricing/model data comes from the claude-api skill cached 2026-06-24 (≈3 weeks old at today's date 2026-07-13); Haiku pricing is stable but should be re-checked against platform.claude.com/docs/en/pricing.md before hard-coding cost assumptions into a paid-tier business model.
- Speech-to-text explain-back transcripts can be noisy (filler words, mis-transcribed technical terms like 'MCP' → 'M C P' or 'empty'); grade leniently on jargon_flags for dictated input or normalize transcripts before grading.
- Free-tier abuse of the grading endpoint (it's an open LLM call surface): without per-user quotas, auth checks in the edge function, and payload size limits (~1,000-char explanation cap), costs and prompt-injection risk are unbounded; also strip/ignore any instructions embedded in learner explanations (treat as data, never as instructions).
- Explain-back content stored in Supabase is user-generated learning data tied to accounts — cover it in the privacy policy and keep it out of leaderboards; only aggregate misconception statistics should feed the distractor bank.
- Several MCP servers in this environment (Vercel, PostHog, Supabase, Vanta) are unauthorized in non-interactive sessions — future build phases that need the Supabase MCP tooling will require the user to authorize via claude.ai connector settings or /mcp in an interactive session.
